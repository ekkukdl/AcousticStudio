# 기존 PCB 제작 방식·회로 분석 및 후속 설계 기준

분석일: 2026-10-06. 대상은 AcousticStudio_ver2의 `구상도`에 보관된 KiCad P0 패널, 조립 견적 패키지, 최신 Creo V2 및 참고 SonicSurface FPGA 소스다. 기존 설계·Gerber·BOM은 변경하지 않았다. 실물 제작·납품·작동 완료 여부를 증명하는 기록은 이번 검토에서 확인하지 않았다.

## 1. 어떤 버전을 기준으로 재설계해야 하는가

| 구분 | PCB 한 장 | 기판 수 | 송신기/독립 출력 수 | 방사면 간 거리 |
|---|---|---:|---:|---:|
| 6면 | 60×180×1.6 mm, 16채널 | 6 | 96 | 150 mm |
| 초기 8면 | 48×180×1.6 mm, 16채널 | 8 | 128 | 150 mm |
| 최신 Creo V2 8면 | 동일한 48×180×1.6 mm, 16채널 | 16 | 256 | 300 mm |

최신 8면은 면당 2장을 나란히 놓고 가운데 20 mm 틈을 둔다. 면당 32채널이지만 PCB 한 장이 32채널인 것은 아니다. 전체 외곽은 약 355×355×180 mm다. 보드당 송신기는 2열×8행, 폭 방향 중심 간격 18 mm, 길이 방향 20 mm다.

중요한 자료 차이: `polygon_panels/panel_8faces_16ch/array_positions.json`은 **128개·방사면 간 거리 150 mm의 초기 좌표**다. 최신 V2 256채널 배치 입력으로 사용할 수 없다. `creo_tunnel/v2_dual_panel` 및 `outputs/creo_tunnel_reused_v2`의 최신 기하 자료를 기준으로 좌표계·법선·PCB 번호·채널 번호를 새로 정의해야 한다. 3D 배치 행렬만으로 전기 채널 순서까지 확정되지는 않는다.

## 2. 설계·제작 방식

기존 SonicSurface의 Gerber 연결 분석과 회로 자료를 참고하여 새 KiCad 회로도와 PCB를 작성한 방식이다. 원본 기판의 단순 확대·축소가 아니다. 부품 심벌과 풋프린트를 프로젝트 내부 `Levitation.kicad_sym` 및 `Levitation.pretty`로 보관해 수정할 수 있다.

설계 파일은 `outputs/polygon_panels/panel_6faces_16ch`와 `panel_8faces_16ch`의 `.kicad_pro`, `.kicad_sch`, `.kicad_pcb`다. 현존 스크립트는 Gerber 묶음, PCB 치수 추출, BOM/PnP 생성·검증 및 Creo 구성 작업을 담당한다. 이번 검색에서는 최초 회로도·배선 전체를 재생성하는 스크립트를 확인하지 못했으므로 KiCad 원본을 수정 기준으로 삼는다.

제조 사양은 2층 FR-4, 두께 1.6 mm이며 F.Cu/B.Cu 양면에 배선과 GND 영역이 있다. 전면은 안쪽을 향하는 송신기 16개, 후면은 IC·저항·커패시터·커넥터가 배치된다. 실제 공정은 다음과 같이 구분한다.

1. PCB 제조: 동박·마스크·실크·외곽 Gerber와 드릴 파일로 기판 제작.
2. 후면 SMT: 레지스터 2개, 드라이버 8개, NPN 1개, 저항 25개, 세라믹 커패시터 19개. 총 55개/장.
3. THT 조립: 전면 송신기 16개, 후면 헤더 2개와 전해 커패시터 1개. 총 19개/장. SMT와 별도로 업체의 삽입 실장·수작업 납땜 포함 여부를 확인해야 한다.
4. 조립 검증: 뒤쪽 송신기 리드 돌출과 후면 부품 간섭, 극성, 고정홀·프레임 공차, 출력 파형 확인.

최신 8면 전체는 16장, SMT 880개, THT 304개, 합계 1,184개다. 업체 BOM 수량은 한 장 기준이고 제작 장수만 16장으로 지정한다. 전원공급기·FPGA·케이블·프레임은 패널 BOM에 포함되지 않는다.

Gerber 견적 ZIP은 `polygon_panels/gerber_quotes`, 조립 BOM/PnP와 DOILLABS 업로드 양식은 `polygon_panels/pcba_8faces_16boards`에 있다. SMT 좌표는 Bottom, mm, Gerber와 동일 원점이며 Y가 음수다. 임의로 Bottom X를 다시 반전하지 말고 업체 미리보기로 회전·원점 규칙을 확인한다.

## 3. 회로가 동작하는 원리

```text
PC의 위상 명령 → FPGA의 채널별 파형 생성
                       ↓ DATA_A / DATA_B + SHIFT / LATCH
               U1 / U2: 74HCT595, 5 V
                       ↓ IN00~IN15
               U3~U10: TC4427A, 듀얼 드라이버
                       ↓ OUT00~OUT15
               T1~T16: 송신기 한 핀 구동 / 다른 핀 GND

ARM → R17 → Q1 → 두 레지스터의 /OE 제어
외부 +5 V → 논리 / 외부 DRV_VDD → 드라이버 / GND 공통
```

### 파형 생성과 직렬 데이터

U1과 U2는 각각 별도 DATA를 받아 8출력을 만든다. 두 레지스터의 SHIFT와 LATCH는 공유하며 직렬 출력 9번 핀은 사용하지 않는다. 여러 PCB를 하나의 DATA로 길게 데이지 체인하는 회로가 아니다. 이 방식으로 6면 96채널은 DATA 12개, 초기 128채널은 16개, 최신 256채널은 **32개**가 필요하다.

74HCT595에는 주파수·위상 값을 해석하는 기능이 없다. FPGA가 각 순간의 8채널 HIGH/LOW 비트를 SHIFT로 보내고 LATCH로 동시에 갱신해야 한다. PC가 전송하는 위상 바이트와 PCB 커넥터 DATA의 파형 비트는 서로 다른 단계다.

참고 소스 `simulations/SonicSurface/Firmware/FPGA primary/src/AllChannels.vhd`에는 256개의 PhaseLine을 32개의 Mux8 직렬 출력으로 묶는 구조가 있다. `PhaseLine.vhd`는 32단계 위상 카운터를 사용한다. 40 kHz·32단계·8비트 직렬화라는 조건에서 계산한 데이터 전송률은 DATA당 10.24 Mbit/s이며, 실제 SHIFT/LATCH 간격과 클록은 BDF·PLL·보드 파형으로 확인해야 한다. 일반 GPIO로 위상 값만 한 번 보내는 방식으로는 지속 파형을 만들 수 없다.

QSF에 DATA[0..31], SHIFT_CLOCK_1/2, LATCH_CLOCK_1/2의 FPGA 칩 핀 할당이 있다. 이는 256채널 연결 후보가 있다는 의미이며, 사용 중인 코어 보드 헤더·분배 회로·ARM 할당까지 호환성이 검증됐다는 뜻은 아니다.

로컬 채널 0~7은 U1의 핀 15,1,2,3,4,5,6,7 → U3~U6 → T1~T8이고, 8~15는 U2 → U7~U10 → T9~T16이다. 직렬 비트 전송 순서와 레지스터 QA~QH의 최종 대응은 별도로 확인해야 한다. 후속 배열에서는 전역 채널, 면 번호, 면 안의 두 PCB 번호, 레지스터 DATA 번호, 물리 출력의 관계를 표로 고정한다.

### 논리 전원과 드라이버

논리 전원은 +5 V이며 HCT 계열은 TTL 입력 임계값을 갖는다. TI 자료의 HIGH 최소 2 V 조건은 정상적인 3.3 V FPGA 신호를 받는 설계 의도와 맞는다. HC형으로 자동 대체하면 입력 임계값을 다시 검토해야 한다. [TI 데이터시트](https://www.ti.com/lit/ds/symlink/sn74hct595.pdf)

TC4427A는 비반전 듀얼 MOSFET 게이트 드라이버를 송신기 구동에 사용한 것이다. 소자 전원 동작 범위는 4.5~18 V, 입력 HIGH 최소는 2.4 V다. 출력 한 개씩을 송신기에 연결하며 송신기의 다른 핀은 GND다. 브리지 회로가 없으므로 이상적인 출력은 약 0~DRV_VDD이고, 부하 양단 전압은 약 DRV_VDD Vpp다. 실제 부하 파형·링잉은 계측해야 한다. 1.5 A 표기는 피크 드라이버 능력이며 패널의 연속 소비전류가 아니다. [Microchip 데이터시트](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/TC4426A-TC4427A-TC4428A-1.5A-Dual-High-Speed-Power-MOSFET-Drivers-20001423.pdf)

회로에는 DC/DC, 승압기, 외부 브리지 MOSFET, 전류 계측, 과전류 차단이나 온도 계측이 없다. 입력 보호·전원 감시도 별도로 설계해야 한다. 필요한 공급 전류와 방열은 송신기 정전용량·전압·주파수와 실측으로 산정하며, 알려지지 않은 연속 구동 정격을 impulse 정격으로 대신할 수 없다.

### ARM과 초기 상태

- R19 10 kΩ은 OE_N을 +5 V로 올려 기본적으로 레지스터 출력을 비활성화한다.
- ARM HIGH → R17 10 kΩ → Q1 베이스 → Q1이 OE_N을 낮춤 → U1/U2 출력 활성화.
- R18 100 kΩ은 Q1 베이스를 접지로 당긴다. R1~R16 10 kΩ은 레지스터가 고임피던스일 때 드라이버 입력을 LOW로 유지한다.
- R20/R21 33 Ω은 SHIFT/LATCH 직렬 저항이고 R22~R25 100 kΩ은 DATA/클록 입력 풀다운이다.

ARM은 드라이버 전원을 끊는 스위치가 아니다. 전원이 정상인 조건에서 레지스터 출력과 입력 풀다운을 통해 출력을 LOW로 유도한다. /SRCLR은 +5 V에 고정돼 있어 자동 데이터 초기화가 없고, /OE 제어도 내부 데이터를 지우지 않는다. 따라서 ARM LOW → 전원 안정 → 유효한 데이터 전송·래치 → ARM HIGH 순서가 필요하다. 전원 상실, 역급전, FPGA 정지까지 차단을 보장하려면 감시 회로와 펌웨어 정책을 추가 검토해야 한다.

### 커넥터와 디커플링

J1 핀 1~10: GND, +5 V, DATA_A, GND, DATA_B, GND, SHIFT_PIN, LATCH_PIN, ARM, GND.

J2 핀 1~3: DRV_VDD, GND, +5 V. J1과 J2의 +5 V는 같은 망이다. 논리/드라이버 전압은 구분하지만 접지는 공통이다. 패널 안에 전압 변환 기능은 없다.

C1~C8은 드라이버별 100 nF, C11~C18은 드라이버별 1 µF, C19는 DRV_VDD 벌크 220 µF다. C9/C10은 레지스터별 100 nF이고 C20은 논리 전원 10 µF다. 용량뿐 아니라 부품 치수·전압·MLCC의 DC 바이어스에 따른 실효 용량을 함께 확인한다.

## 4. 재검사 결과와 해석 범위

이번에 KiCad CLI **10.0.6**으로 두 원본 회로도의 ERC, PCB DRC와 회로도 일치 검사를 새로 실행하고 XML 넷리스트를 새로 출력했다. KiCad Python API로 현재 PCB와 새 넷리스트를 직접 비교했다.

| 확인 항목 | 6면 PCB | 8면 PCB |
|---|---:|---:|
| ERC 보고 위반 | 0 | 0 |
| DRC 보고 위반 | 0 | 0 |
| 미연결 / 회로도 불일치 | 0 / 0 | 0 / 0 |
| 비교한 연결 패드 | 234 | 234 |
| 패드 넷 차이 | 0 | 0 |
| 전기 부품 / SMT / THT | 74 / 55 / 19 | 74 / 55 / 19 |
| 트랙 선분 / 비아 | 698 / 63 | 704 / 57 |
| 최소 트랙 폭 | 0.1874 mm | 0.1874 mm |

과거 문서의 216패드 수와 달리 이번 검사는 현재 PCB의 넷 이름이 있는 모든 패드를 비교했다. 수량 차이를 설계 변경의 증거로 해석하지 않는다. 8면 PCB·기존 XML·견적 Gerber ZIP의 SHA-256은 조립 패키지의 `validation_and_sources.json` 기록과 모두 일치했다.

검사 규칙에 한계가 있다. DRC 보고서에는 missing_courtyard, track_not_centered_on_via, tuning_profile_track_geometries, footprint_filters_mismatch, footprint_type_mismatch의 **5개 ignore 항목**이 있다. 프로젝트의 개별 DRC 제외 목록은 비어 있지만 모든 검사 종류가 활성화된 상태는 아니다. 특히 custom 풋프린트의 조립 여유·부품 몸체 간섭과 제조사 DFM을 0건 결과로 보증할 수 없다. ERC에도 4개 ignored_checks가 있으며 세부 항목은 원본 보고서에 보존했다.

DRC의 일반 최소 간격은 0.20 mm, 드라이버 전원 넷 클래스는 0.25 mm, 최소 허용 트랙 폭은 0.15 mm다. 일부 신호 탈출부의 실제 폭 0.1874 mm는 설정된 규칙을 만족한다. 공급 전류에 적합한 동박 폭·두께·온도 상승을 따로 계산한 결과는 아니다.

## 5. 다음 제작 전에 해결할 사항

1. **업체 0.002 mm 간격 오류:** 기존 조립 안내에 미해결로 기록돼 있다. 이번 KiCad 재검사만으로 그 오류가 없어졌다고 판단할 수 없다. 업체가 지적한 층·좌표·객체 쌍과 실제 업로드 ZIP을 받아 동박, 같은 넷 경계, 마스크, 드릴 중 무엇인지 판별해야 한다. 현재는 발생 원인을 단정하지 않았다.
2. **U1/U2 품번 일관성:** 회로도·PCB 값은 `SN74HCT595D`, SMT BOM 구매 후보는 Nexperia `74HCT595D,118`이다. 실제 풋프린트는 SO16 3.9×9.9 mm, 피치 1.27 mm다. 검토한 TI SN74HCT595 데이터시트의 주문 정보는 TSSOP(PW)이며 이 SO16 풋프린트의 구매 근거로 사용할 수 없다. Nexperia 자료는 74HCT595D의 SO16을 명시한다. 새 설계에서는 제조사·MPN·패키지·회로도 값·BOM을 통일해야 한다. [Nexperia 데이터시트](https://assets.nexperia.com/documents/data-sheet/74HC_HCT595.pdf)
3. **송신기 확정:** 표시 V40AN16T의 실제 공급사·40 kHz 송신형·Ø16 mm·10 mm 핀 간격·리드 굵기·높이·연속 입력 정격을 확정한다. 음향 극성은 실물로 확인하고 채널별 보정한다.
4. **256채널 연결:** DATA 32개, 클록 두 그룹과 ARM의 배선·FPGA 헤더·GPIO를 결정한다. 긴 케이블과 다수 패널 부하는 클록 분배 버퍼·귀환 경로·파형으로 검증해야 한다. PCB 쪽 33 Ω만으로 전체 분배 품질은 확정되지 않는다.
5. **최신 좌표와 PC 통신:** 새 256좌표·법선·물리 채널 맵을 작성한다. `src/acousticstudio/hardware.py`는 256개 위상의 엄격한 프레임 길이 검사와 물리→소프트웨어 채널 맵 기능을 갖지만 새 패널 연결을 자동 추론하지 않는다. 기존 프로파일을 선택하는 것만으로 핀 순서가 맞아지는 것은 아니다.
6. **전원·조립·성능:** 전원/커넥터 전류 정격, 퓨즈·역극성 보호 필요성, 바닥면 전자부품과 리드/프레임 간섭, GND 직접 연결 패드의 납땜성을 검토한다. 한 패널에서 출력·위상·ARM·리플·온도를 확인한 뒤 전체 배열로 확장한다. 300 mm 터널의 음장·복원력·부양 성능은 새 좌표로 다시 계산하고 실험해야 한다.

## 6. 후속 변경 작업에 적용할 기준

사용자가 변경 요구를 주면 그 요구에 맞춰 면 수, 면당 PCB 수, 채널 수, 송신기 치수·배치, 터널 거리·촬영 틈, 구동 전압, 제어 보드, 조립 범위를 확정한다. 기존 설계는 보존하고 별도 리비전으로 회로도·PCB·필요한 라이브러리·제조 파일·BOM/PnP·핀/채널 맵·배열 좌표를 함께 갱신한다. 기구 치수가 바뀌면 Creo 참조 모델도 해당 범위에서 맞춘다.

검증은 회로도↔PCB 연결, ERC/DRC, 풋프린트/MPN, 조립 방향, Gerber 원점, 기구 간섭, 소프트웨어 좌표·채널 순서까지 구분해 기록한다. 실제 FPGA 컴파일·계측·부양 실험은 실행 여부와 결과를 별도로 적는다. 구체적인 변경 요구는 아직 받지 않았으므로 새 회로 제작이나 기존 오류 수정은 이번 분석 범위에 포함하지 않았다.
