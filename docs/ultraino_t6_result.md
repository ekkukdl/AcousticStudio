# T6 단면 조작·궤적 이송 — 2026-10-08

단면 클릭/드래그, 선택·전체 제어점의 XYZ 이동, 비동기 위상·음장·궤적 진단·내보내기,
최신 프레임 송신 큐를 구현했다. 소프트웨어 및 fake-serial 검증 완료이며 실제 터널 이송은 미검증이다.
Creo R2의 8면·8기판·256채널 방사면 좌표와 법선, T2 음장 및 T5 보정·맵·OFF 인코더를 유지했다.

2026-10-08 연속 이동 회귀 수정: 제어점 이동 때 단면 작업을 취소하고 숨기던 동작을 수정했다.
마지막 완성 단면을 유지하고 실행 중인 단면 작업이 끝나면 표시한 뒤 최신 위상으로 다시 계산한다.
음원 형상·보정·단면 설정이 바뀐 결과는 계속 거절하며, 하드웨어에는 최신 검증 위상만 송신한다.
자동 계산을 켜야 이동에 따른 위상과 단면이 갱신된다. 계산이 느리면 화면은 완성된 스냅샷 단위로 갱신된다.
`음장 → 음장 분석 → 단면 갱신 간격`에서 1~5000 ms를 직접 입력할 수 있다. 기본값은100 ms이며
프로젝트·Undo/Redo에 저장된다. 빠른 반응이 필요하면20~50 ms부터 조절한다. 이 값은 계산 시작의 최소 간격이고
실제 갱신은 계산 완료 속도에 제한된다. 실행 중인 계산은 간격 변경만으로 취소하지 않는다.
수정 후 T6 집중22 passed, 전체250 passed/4 skipped를 확인했다.
[수정 회귀 기록](../scratch/ultraino_migration/field_motion_fix_full_pytest.xml).

## 사용 방법

앱을 저장하고 다시 실행한다. `구성 → 제어점` 아래에 이동 조작이 있다.

1. 목록에서 이동할 제어점을 선택하고 `이동 대상`을 선택 제어점 또는 전체 제어점으로 정한다.
2. `단면 클릭·드래그로 이동`을 체크하고 XZ·YZ·XY 중 평면을 고른다.
   평면 위치는 기존 `음장 → 음장 분석`의 동일 이름 단면 위치 값이다.
   XZ는 Y 고정, YZ는 X 고정, XY는 Z 고정이며 터널 이송 축은 Z다.
3. 3D 뷰포트에서 클릭하거나 드래그한다. 이동 대상의 중심이 해당 세계 좌표로 이동하며
   여러 제어점 사이 간격과 각 트랩 종류·방향·가중치는 유지된다. 버튼을 놓은 최종 위치도 반영한다.
   체크를 해제하면 기존 왼쪽 클릭 선택 기능을 사용한다. 오른쪽 드래그 카메라 조작은 유지된다.
4. `이동 간격`과 X−/X+·Y−/Y+·Z−/Z+로 이동할 수도 있다.
   전체 제어점에는 비활성 제어점도 포함하지만 위상 계산은 활성 체크된 제어점만 사용한다.
5. 궤적을 생성하고 정방향·역방향 재생 버튼을 누른다. 선택·전체 제어점의 중심이 궤적을 따라 이동한다.
   첫 위치와 마지막 위치를 포함하며 이전 위치의 계산 및 실시간 송신이 끝나야 다음 위치로 진행한다.
   일시 정지와 `이동·계산 중지`는 대기 계산/프레임을 폐기한다. 이미 전송한 마지막 위상을 OFF로 바꾸지는 않는다.
6. 궤적 물리 진단과 내보내기는 별도 작업에서 수행하며 `이동·계산 중지`로 취소할 수 있다.
   오류·설정 변경·취소 결과는 저장하지 않는다. 이동 설정은 프로젝트·Undo/Redo에 저장한다.

기존 궤적 내보내기는 **waypoint마다 한 목표**의 파일이다. 여러 선택 제어점의 간격을 유지하는
동시 이송 재생과 구분한다. 다중 재생은 T4 혼합 목표를 유지하고 내보내기는 기존 단일 목표 계약을 유지한다.
음압·상대 강도 지표를 실물 부양 성공률로 표시하지 않는다.

## 계산과 송신 계약

- `motion.py`는 mm 단위 광선/평면 교차와 그룹 이동을 담당한다. 세계 좌표는 VTK의 근·원거리
  역투영으로 계산하고 HiDPI 배율과 Qt/VTK Y축 변환은 기존 이벤트 필터에서 적용한다.
  평행한 카메라 방향과 카메라 뒤쪽 평면은 이동 좌표를 만들지 않는다.
- `motion_ui.NumericalController`는 기존 `HologramController`의 QThread 종료·취소·최신 요청 관리를 재사용한다.
  작업별 실행 중 1개/최신 대기 1개만 보관한다. 작업자는 복사한 숫자·설정만 받으며 Qt/VTK 장면을 읽지 않는다.
  위상·진단·내보내기는 요청 번호와 입력 해시가 맞을 때만 GUI 스레드에서 결과를 적용한다.
  단면은 음원·보정·평면·표시 설정이 같으면 이전 완성 위상 스냅샷도 표시하고 최신 위상으로 후속 계산한다.
- live 위상 갱신은 최소 33ms 간격, 음장 요청은 사용자 지정 간격(기본100ms), 이동 렌더링은 33ms로 병합한다.
  느린 계산 중 드래그 요청은 최신 위치로 합친다. 궤적 재생은 이전 위상이 준비될 때까지 현재 waypoint를 유지한다.
  음장 계산 취소는 512개 수신점 단위, 궤적/진단 취소는 waypoint 및 Kinoforms 반복 경계에서 확인한다.
  Taichi 공통 복소 합산은 잠금으로 직렬화한다.
- `hardware.queue_phases`는 기존 공통 프레임 인코더로 보정→맵→양자화/OFF를 적용한다.
  실행 중 write 1개와 최신 대기 프레임 1개만 유지한다. 실시간 write는 별도 QThread이며
  기존 0.1초 write_timeout, 부분 쓰기/timeout 시 연결 종료 및 재시도 없음 원칙을 유지한다.
  큐는 최대 30Hz와 실제 프레임 길이의 8N1 선로 시간 중 느린 조건을 적용한다.
- 중지·연결 해제·설정 변경 시 대기 프레임은 폐기한다. 재연결 후 이전 세션의 완료 결과나
  프레임을 재송신하지 않는다. 이미 시작한 write는 되돌릴 수 없으며 로컬 write 성공은 보드 ACK가 아니다.
  수동 전송과 실시간 write가 겹치면 수동 전송은 실패 사유를 표시한다. write 완료 후 사용자가 다시 전송할 수 있다.
- 창 닫기는 계산 및 송신 작업이 끝난 뒤 진행한다. 저장 취소 시 창을 유지한다.

### 갱신 스트림 실측

[재현 도구](../scratch/ultraino_migration/verify_t6_updates.py)는 혼합 2트랩·256채널·12회 고정 반복을
warm 상태에서 nominal 33ms 타이머로 30회 요청했다. 실제 Qt 타이머 지연과 작업 생성 비용도 포함한다.
[측정 원본](../scratch/ultraino_migration/t6_updates_result.json)은 fake serial 결과이며 실제 선로/ACK 측정이 아니다.

| 엔진 | 요청/적용/프레임 | 스트림 종료까지 | 마지막 응답 | 적용 계산 시간 |
|---|---|---|---|---|
| C++ | 30 / 30 / 30 | 1.430초 | 23.84ms | 약17.93~20.93ms |
| Taichi Vulkan | 30 / 1 / 1 | 1.588초 | 78.77ms | 마지막 계산71.83ms |

Vulkan은 29개 요청을 최신 요청으로 병합했고 최종 phasor 오차는 CPU 기준1.83e-15 미만이다.
마지막 프레임은 기존 live 인코더와 일치했다. 이 때문에 재생은 계산/송신 완료를 기다리도록 했다.
현재 작은 혼합 목표 문제에는 C++이 더 빠르다. nominal 30Hz 요청을 실제 보드의 30Hz 지속 갱신으로 해석하지 않는다.
230400 baud·258byte·8N1의 선로 시간만 약11.2ms이며, 장치/드라이버와 계산에 따라 더 느리다.
