# AI 에이전트 코드 수정 및 백업 가이드라인 (AI Agent Guidelines)

**모든 AI 에이전트(서브에이전트 포함)는 이 프로젝트의 코드를 수정할 때 반드시 아래의 백업 프로토콜을 준수해야 합니다.**

## 1. 코드 수정 전 백업 (Pre-edit Backup)
어떤 코드를 수정하기 직전, 반드시 해당 파일의 현재 버전을 동일한 폴더 내에 `_backup` 접미사를 붙여 백업하십시오.
- 예: `src/acousticstudio/app.py` 수정 전 -> `src/acousticstudio/app_backup.py` 로 복사(덮어쓰기).
- PowerShell 명령어 예시: `Copy-Item -Path "src\acousticstudio\app.py" -Destination "src\acousticstudio\app_backup.py" -Force`

## 2. 코드 수정 및 검증 (Modify & Verify)
백업이 완료되면 본 코드를 수정하고 컴파일/실행 테스트를 진행합니다.

## 3. 롤백 및 확정 (Rollback or Commit)
- **문제가 발생할 경우**: 백업해 둔 `app_backup.py`를 원본으로 다시 덮어씌워 롤백한 후 원인을 분석합니다.
- **문제가 없을 경우**: 수정된 코드가 그대로 유지되며 테스트를 통과한 상태로 둡니다.

## 4. 백업 갱신(덮어쓰기)의 엄격한 기준 (Strict Backup Update Criteria)
백업 파일(`app_backup.py`)을 현재 코드(`app.py`)로 덮어씌워 갱신하는 시점은 **오직 사용자가 "괜찮다, 정상 작동한다"고 명시적으로 확정(Confirm)하고 다음 새로운 기능을 개발하자고 넘어가는 시점**뿐입니다.
- **오류 수정 과정 중 백업 갱신 절대 금지**: 특정 기능을 넣기 위해 발생하는 에러를 잡고 디버깅하는 '시행착오(Trial & Error)' 과정 도중에는 절대로 백업 파일을 새로운 코드로 덮어쓰지 마십시오.
- 이 규칙은 디버깅 중 코드가 걷잡을 수 없이 꼬일 경우, 사용자가 "괜찮다"고 했던 가장 마지막 안전한 상태(최후의 백업본)로 언제든지 돌아갈 수 있게 하기 위함입니다.

## 5. 프로젝트 진행 상황 지속 업데이트 (Continuous Progress Update)
모든 에이전트는 사용자의 요청을 성공적으로 수행하여 특정 기능 구현이나 버그 수정이 완료될 때마다, 반드시 **`docs/project_status.txt`** 파일을 열어서 다음 항목들을 최신 상태로 유지해야 합니다:
- **진행한 부분 (완료된 작업)**: 방금 해결한 버그나 새로 추가한 기능을 명확히 기록.
- **현재 진행 상황**: 전체 프로젝트 관점에서의 현 위치 요약.
- **진행해야 될 부분 (To-Do)**: 아직 구현되지 않은 남은 과제나 다음 목표를 갱신.
이 과정을 통해 사용자와 AI, 그리고 릴레이로 작업하는 다른 AI 서브에이전트들이 항상 동일한 목표와 최신 진행 상황을 공유할 수 있도록 합니다.


## 6. GitHub 푸시(Push)에 대한 엄격한 기준 (Strict GitHub Push Criteria)
깃허브 저장소에 코드를 푸시(Push)하는 행위는 **백업 파일을 덮어씌우는 것과 완전히 동일한 규칙**을 따릅니다.
- **AI 자체 테스트 결과에 의존한 푸시 절대 금지**: AI가 스스로 디버깅이나 스크립트 실행을 통해 "성공했다"고 판단하더라도 절대 푸시해서는 안 됩니다. AI의 자체 테스트 성공은 푸시의 조건이 될 수 없습니다.
- **푸시 가능 시점**: 오직 **사용자가 직접 로컬에서 프로그램을 켜서 테스트해 보고 "이 기능은 이 정도면 됐다", "완벽하게 작동한다"라고 명시적으로 승인(Confirm)** 했을 때만 커밋(Commit) 및 푸시(Push)를 수행합니다.
- **오류 수정 중 푸시 절대 금지**: 특정 기능을 추가하거나 에러를 고치기 위한 '시행착오(Trial & Error)' 과정 중에는 절대로 깃허브에 푸시하지 마십시오. 실제 사용자의 검증이 완료된 최종 안전본만 깃허브에 기록되어야 합니다.
---
*이 규칙은 사용자의 명시적인 요청에 의해 제정되었으며, 파일이 손상되거나 코드가 꼬이는 것을 방지하기 위한 절대적인 안전 장치입니다.*

## 7. 작업 후 잔여 파일 정리 (Clean Up Residual Files)
특정 기능 구현이나 오류 수정을 위해 임시로 생성한 테스트 스크립트(`test_*.py`), 디버깅 파일(`debug_*.txt`), 수정 스크립트(`fix_*.py`) 등은 작업이 성공적으로 마무리된 후 **반드시 삭제하여 작업 디렉터리를 깔끔하게 유지**해야 합니다. 단, 코드 안전을 위해 생성한 백업 파일(`_backup.py`)은 사용자가 최종 확정(Confirm)을 내리기 전까지는 유지하며, 승인 이후 깃허브 푸시 과정에서 정리하거나 사용자의 명시적인 지시가 있을 때 정리합니다.
